# M6030G9 · CANopen 一体减速伺服电机 — 协议笔记与工具链

翼志 / 时代超群 **M6030G9**（100 W、9:1 行星减速、CANopen）在三轮全向底盘上的实机调试记录。
所有协议细节、报文格式、踩坑结论都来自**实测**，不是照抄手册 —— 手册与实际不符的地方都标了出来。

## 这台电机是什么

| 项目 | 值 |
| --- | --- |
| 型号 | M6030G9（时代超群，电机/驱动器由杭州翼志供货） |
| 类型 | 一体减速伺服（内置驱动 + 9:1 行星减速） |
| 额定 / 最大转速 | 电机 1500 / 2000 rpm |
| **输出轴转速** | **0 ~ 166 rpm**（额定，9:1 减速后） |
| 输出扭矩 | 9 N·m |
| 额定电流 | 3.5 A（`261Dh = 7003`，单位 mA） |
| 母线电压 | 24 ~ 36 V |
| 编码器 | 15 位单圈（32768）/ 16 位多圈 |
| 通讯 | CANopen（CiA301 V4.2.0），1 Mbps |

> ⚠️ **最容易被忽略的一点**：`60FFh`（目标速度）是**电机转速**，不是输出轴转速。
> 想要轮子转 150 rpm，必须下发 `60FF = 1350`。

## 快速开始

### 1. 拿到底层 DLL

创芯 USB-CAN 的 `ControlCAN.dll` **需要从厂商获取**（本仓库不包含，版权与体积原因）：

- 官网资料下载页：<https://www.zhcxgd.com/1.html>
- 下载《CAN分析仪二次开发示例源代码》包，取其中的 **64 位** `ControlCAN.dll`
  （路径示例：`python(x64)/python3.8.0推荐/ControlCAN.dll`，约 2.68 MB）
- 放到本仓库 `python/` 目录下（与 `aim_can.py` 同级）

> **32 位 DLL 无法被 64 位 Python 加载**，这是最常见的失败原因。
> 也可以用 32 位 Python 配 32 位 DLL，但换 USB 口后容易出现设备找不到的问题。

### 2. 运行

```bash
cd python
python examples/scan_bus.py          # 先确认有几台在线上
python examples/verify_station.py    # 再确认 PDO 实际地址
```

`aim_can.py` 默认使用 **TX 走通道 0、RX 走通道 1**（本机实测通道 0 接收不工作）。

## 踩过的坑（按严重程度）

### 会导致设备失控

1. **`607Ah` 是无符号 32 位** —— 目标位置一旦变负会绕成约 42 亿，电机朝那个方向全速狂奔。
   目标必须限幅 `[0, 2³¹-1]`；位置接近 0 时要把零点整体重取。
2. **位置模式会无限期执行最后一个目标** —— 上位机崩溃后伺服仍朝旧目标跑。
   建议启用 `1016h` 看门狗（如 `0x7F01F4` = 500 ms）+ 主机每 200 ms 发 `0x77F` 心跳。
3. **`0x0F` 不能出现在位置流里** —— 会让运动反复中断（一台卡顿、一台不动）。位置跟随只发 `0x2F`。

### 会让你怀疑硬件

4. **`0x600` 是 SDO 广播** —— 所有伺服都会响应，配置会一起被改。单台配置要用 `0x600+站号`，或只接一台。
5. **改站号不会自动更新 PDO 的 COB-ID**，且 PDO ID 改动**要断电重启**才在通讯中生效。
6. **`6041h`/`6040h`/`2601h` 读回不可信** —— 判断状态只能看 `606Ch`（速度）与 `6064h`（位置）。
7. **64 位 Python 加载不了 32 位 DLL**。
8. **创芯卡通道 0 收不到数据**，TX/RX 必须分通道。
9. **插头版本的 CAN 需要外部供 5 V**（`CAN_5V` + `COM`），掉了以后电机照常跑但通讯静默失联。

### 浪费时间但无害

10. `2614h=1` 保存参数会**清零位置计数**。
11. `261Dh = 7003` = 3.5 A；限到 `100`（0.1 A）可让电机"没力"，适合当手转主轴。
12. `1017h = 0` 表示心跳关闭，被动监听会误以为"链路断了"。
13. `260Ah` 电子齿轮**只影响脉冲+方向通道**，用 CANopen 时三台刻度天然一致。
